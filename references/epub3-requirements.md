# EPUB3 requirements

Generated books must contain an uncompressed first `mimetype` entry, `META-INF/container.xml`, an EPUB3 OPF package, XHTML content, navigation, manifest, and spine. Canonical conversions bundle all reading assets locally; EPUB passthrough may retain standards-compliant HTTP(S) remote resources declared by the source publication. EPUBCheck errors fail conversion; missing EPUBCheck produces a warning and internal ZIP/package validation still runs. CSS must remain reflowable, images responsive, tables bounded, and code wrappable. Existing EPUB2 inputs remain valid passthrough publications and are checked for an OPF manifest, spine, NCX navigation, and local spine content.

To bound memory use on untrusted archives, internal validation requires Expat 2.6.0 or newer and parses no more than 64 MiB for any individual XML or CSS resource, 2 MiB per JavaScript resource, 20,000 unique references per resource, and no more than 256 MiB of parsed resources in total. XML parsing stops at 200,000 elements or 4,096 levels per resource, and CSS function nesting stops at 4,096 levels. JavaScript parsing stops after 2,500,000 parser operations per publication, and AST inspection stops at 500,000 syntax-node and scope-resolution steps. Embedded data URLs are allowed without separate manifest entries; package links, top-level browsing links, statically identifiable `window.open`/`document.open` calls and aliases that use data URLs, and `iframe[srcdoc]` content that cannot be safely inspected are rejected. Unparsed binary media are excluded from the byte budget.
